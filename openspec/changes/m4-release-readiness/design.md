# Design: M4 数据可移植性、桌面集成与 v1.0 发布

## Context

M1–M3 已形成可工作的 Tauri 2 + React 19 应用：Rust 侧 `AppStateInner` 持有 meta/tasks/calendar 与各空间的长期 SQLite 连接，数据库均使用 WAL 和版本化迁移；笔记附件与任务附件在数据库外以内容哈希存放；加密分区的 DSK 仅存在会话内；三类 FTS 查询已分别存在但没有聚合入口。前端根组件使用 hash 路径切换三大模块，各模块各自维护 UI 与 API，目前绝大多数文案为中文，CSS 已使用部分 `dark:` 变体但没有主题控制器。Tauri 配置仍为模板阶段的 `0.1.0`、通用描述和基础权限，尚无托盘、全局快捷键、文件对话框或发布自动化。

动机和范围见 `proposal.md`，行为契约见本变更的九个 spec delta。本设计必须保持纯本地运行、跨库故障隔离、加密密钥不落盘和锁定内容不参与任何索引/汇总的既有约束。

## Goals / Non-Goals

**Goals:**

- 用一套可测试的 Rust 领域层完成格式转换、备份清单、哈希校验、恢复编排和跨库聚合，Tauri commands 继续保持薄层
- 让备份与恢复在多库、WAL、外置附件和长期连接同时存在时仍具有明确的一致性与回滚语义
- 将命令面板、快捷键和托盘统一映射到同一组应用动作，避免三套行为分叉
- 把主题、本地化和通用设置放到根应用层，使所有模块、对话框和后台反馈使用同一偏好来源
- 让发布产物可复现地通过跨平台质量门槛，且不在仓库中引入签名秘密

**Non-Goals:**

- 不设计通用插件系统或可扩展导入器；v1 格式集合固定
- 不保证任意 HTML/CSS 的像素级 PDF 还原；只保证 Tenjee Vault 支持的文档节点稳定输出
- 不把备份变成增量、可挂载或可逐项恢复的归档系统
- 不通过后台守护进程在应用完全退出时执行提醒或自动备份

## Decisions

### D1: 导入导出使用中间文档模型，解析与渲染全部在 Rust 侧

新增 `src-tauri/src/portability/`，以受限 `PortableDocument` AST 表示标题、段落、文本样式、列表/待办、表格、链接、图片和附件。Markdown、净化后的 HTML、纯文本和 TipTap JSON 分别转换到该 AST，再由 Markdown、HTML 与 PDF renderer 输出。这样格式差异集中在边界层，附件命名、内部链接重写和加密检查只实现一次；PDF 用 Rust PDF 库绘制受支持节点并内嵌项目自带的中英文字体子集，打印则渲染专用只读 HTML 后调用 WebView/平台打印流程。

HTML 导入使用白名单 sanitizer，完全删除脚本、样式 URL、事件属性和远程主动内容；图片只接受用户同时选择或文件相对目录内的本地资源。所有输出先写同目录临时文件/目录，完成后 rename；目标已存在由前端确认后把 `overwrite=true` 传给 command。

**备选**：直接在前端做格式转换（否决，文件系统边界、加密检查和批量原子写入难以统一测试）；用无头浏览器截图生成 PDF（否决，产物大、平台差异大且文本不可搜索）；为每种格式直接转换 TipTap JSON（否决，转换逻辑成对增长）。

### D2: iCalendar 采用严格适配层，内部模型仍以现有事件与 RRULE 为准

`portability/ical.rs` 用 iCalendar parser/serializer crate 处理折行、转义、日期与时区参数，再显式映射到现有 `EventRecord`、`RRule` 和例外模型。只接受现有 RRULE 子集；未知属性进入 warning，不静默改变已知字段。导入前解析整个文件并形成 `ImportPlan`，按 UID 查询冲突，用户选择 update/copy 后再在单个 calendar.db 事务中落库。新增 `external_uid` 保存稳定来源标识。

公历系列直接写 RRULE/RECURRENCE-ID/EXDATE 语义；农历系列要求范围并展开为多个 VEVENT，使用共同 `RELATED-TO` 与私有 `X-TENJEE-LUNAR-SERIES` 仅帮助识别来源，不承诺其他客户端理解农历。导入时这些仍是独立公历事件，避免猜测丢失的规则。

**备选**：完整实现 RFC 5545（否决，远超 v1 范围且会与现有有界 RRULE 冲突）；把农历规则写入自定义 RRULE（否决，外部客户端会错误解释或丢弃）。

### D3: `.tvault` 是清单驱动 ZIP，备份通过全局维护闸门协调

备份包扩展名为 `.tvault`，内部第一项为 `manifest.json`，其后仅允许清单声明的规范相对路径。清单包含格式版本、应用版本、时间、每个文件的类别/大小/SHA-256、各库 schema 版本和空间注册信息。ZIP 提供便携的单文件容器；安全读取器不执行通用解压，只按清单流式读取到随机暂存目录，并拒绝绝对路径、`..`、重复路径、符号链接、未声明项与尺寸上限异常。

`AppStateInner` 新增 `maintenance: RwLock<()>`。所有修改命令持有共享读锁；备份建立短暂独占写锁，按固定顺序锁定 meta → tasks → calendar → 排序后的 spaces，使用 SQLite online backup API 复制数据库到临时目录，同时复制冻结清单内附件，再释放业务锁进行哈希和压缩。这样只阻塞快照窗口，不在整个压缩期间阻塞编辑。快照任一项失败即丢弃临时结果。

**备选**：直接复制 WAL 数据库文件（否决，容易遗漏 WAL/SHM 或跨库时间点混合）；长时间关闭全部连接（否决，备份大附件时阻塞明显）；把数据库和附件分别备份（否决，无法给出完整包一致性）。

### D4: 恢复分成在线验证与启动前交换两个阶段

运行中的 `prepare_restore` 只把包安全展开到 `<root>/restore-staging/<uuid>/`，验证哈希、数据库 integrity、清单/注册表引用和支持的格式版本，然后写入根目录外层的 `pending-restore.json`（包含 staging 路径和 nonce），锁定全部加密会话并请求应用重启。早期 bootstrap 在创建布局或打开任何 SQLite 连接之前读取 marker：把当前数据根 rename 为带时间戳的 `pre-restore` 目录，把 staging rename 到数据根，运行启动迁移与完整性检查；成功后清 marker，失败则把候选移到 `failed-restore` 并原子恢复旧目录。

marker 和 staging 位于数据根的同级目录，以便数据根整体切换且同文件系统 rename 保持原子性。恢复前副本在用户确认或下一次成功备份后才清理。过新的备份格式直接拒绝；旧且声明可迁移的 schema 交给现有迁移链升级。

**备选**：运行中关闭并替换 `Mutex<Connection>`（否决，后台提醒和 commands 的连接生命周期复杂，失败时容易持有陈旧句柄）；逐文件覆盖（否决，崩溃会产生混合版本目录）。

### D5: 自动备份由应用内调度器负责，记录“上次成功”而非排队每个周期

在 meta `app_config` 中保存启用状态、daily/weekly 频率、目标目录、保留数和 `last_success_at`。后台调度器每分钟检查一次；若当前周期尚无成功备份，启动稳定且没有维护任务时创建一份。应用退出期间错过多个周期也只补一份。自动包名含 UTC 时间和随机后缀，成功后仅依据有效 manifest 中 `managed_auto_backup=true` 的包排序并删除超额项，不按文件名或通配符删除。

**备选**：操作系统计划任务（否决，三平台安装/权限/卸载行为差异大）；保存每个错过周期的作业（否决，启动后可能产生备份风暴）。

### D6: 全局动作注册表驱动命令面板、快捷键与托盘

前端 `src/shared/actions/` 定义稳定 action id、i18n label、是否需要窗口/当前上下文及执行函数。命令面板展示动作并调用聚合搜索 command；应用内快捷键映射到 action id。Rust `desktop/` 维护系统级快捷键和 tray menu，触发时向前端发统一 `app-action` event；窗口未创建/隐藏时先显示并聚焦，再分发动作。托盘和窗口 close handler 都调用同一个生命周期控制器；仅明确 `quit` 进入锁定会话、停止调度器、注销快捷键、退出的序列。

快捷键配置先完整校验和尝试注册新集合；全部成功才交换并注销旧集合。系统注册失败不会留下半套配置。默认关闭到托盘为关闭，以避免用户首次点击关闭后误以为应用退出；设置页明确说明后台行为。

**备选**：分别在 React、tray handler 和插件 callback 中实现操作（否决，状态和权限检查会漂移）；所有快捷键都做系统级（否决，侵占系统组合且增加冲突）。

### D7: 聚合搜索并行扇出，排序按域内得分与类型配额合并

新增后端 `search::global`，在短暂获取各连接后并行查询 notes spaces、tasks 和 calendar，每域最多取 `limit`，转成统一 `GlobalHit {kind,id,title,snippet,context,score,route}`。每种 FTS rank 先做域内归一化，再按分数合并，并为每类保留最少配额，避免某一大库吞掉全部结果。空间搜索仍只把 `SessionManager` 中已解锁分区的临时索引纳入；聚合层不缓存内容。前端以 120ms debounce 和递增 request id 丢弃过期响应。

**备选**：建立跨库总索引（否决，会复制内容并破坏加密分区和故障隔离）；前端串行调用三个 API（否决，延迟叠加且排序/取消逻辑重复）。

### D8: 标签仍以 meta 字典为身份，各领域保留本地关联

沿用 `meta.tags` 为全局字典与稳定 id，space/tasks/calendar 各自 `taggings` 只保存 tag id 和实体引用；calendar 新增 taggings 迁移，space 的既有表开始由 UI 使用。聚合查询先读字典，再分别查询领域关联并容错缺失 id。删除标签在维护闸门共享锁内依次清理各库；不使用跨库事务，若中途失败则 meta 字典暂不删除并在下次重试剩余清理。

**备选**：把所有 taggings 移到 meta.db（否决，削弱空间库独立备份与删除）；复制标签名称到每库（否决，重命名一致性差）。

### D9: 模板分为内置、全局明文与分区加密三类

内置模板作为版本化前端资源。自定义全局模板存入 meta.db `page_templates`，使用 TipTap JSON 明文并可用于任意普通分区。用户从加密页面保存模板时，默认建立 `section_templates` 记录并用该分区 DSK 加密内容，只有该分区解锁时可用；明确确认后才允许提取为全局明文模板。模板实例化复制 JSON 并重新生成附件/嵌入节点标识，不保留模板引用。

**备选**：所有模板存 meta 明文（否决，会意外泄露加密内容）；所有自定义模板存某个空间（否决，跨空间使用和空间归档语义不清）。

分区密码移除前必须先处理所有加密分区模板：用户可明确确认导出为全局明文模板后删除分区副本，或直接删除分区模板。只要 `section_templates` 仍有记录，后端拒绝移除密码，保留 DSK 和所有内容，避免留下无法解密的模板；不得自动转为明文。

### D10: 笔记待办关联通过稳定 node id 与 tasks.db 同步队列

扩展 TipTap task item 属性加入随机 `nodeId` 与可选 `taskId`。由待办创建任务时，在 tasks.db 保存 `source_page_ref`、`source_node_id`，并将 task id 写回页面。普通页面的任务状态变化直接通过空间 command 更新对应节点；加密来源锁定时，tasks.db 的 `note_sync_queue` 仅保存引用与目标 checked 状态，不保存页面标题或正文，分区解锁事件再消费。缺失节点或页面将队列项标为失效并在 UI 展示，不自动重建内容。

**备选**：只在前端打开页面时按标题匹配（否决，重名和编辑后不可靠）；让 tasks.db 保存笔记片段（否决，越过加密边界）。

### D11: 本地化用类型化内置词典，主题由根控制器统一应用

v1 只含 `zh-CN` 和 `en`，用 `src/i18n/` 的类型化 key 与两个静态词典，避免为两种内置语言引入运行时下载或大型框架。用户内容、标签和导入数据不翻译。Rust 错误返回稳定 code + 参数，前端负责本地化展示；系统通知由 Rust 根据当前 locale 选择同一小组共享 message id。

根 `PreferencesProvider` 在首次渲染前从系统语言/`prefers-color-scheme` 与持久设置确定 locale/theme，把 `dark` class 与 `lang` 属性设在 document root，并监听系统主题变化。CSS 颜色收敛为语义 token，逐步替换散落的固定色值。

**备选**：gettext/ICU 完整运行时（否决，v1 只有两种语言且无复杂复数需求）；各模块独立读取设置（否决，会闪烁且状态可能不一致）。

### D12: 发布流水线按平台原生构建，签名与自动更新留作独立发布能力

将 package、Cargo 和 Tauri 配置统一到 `1.0.0`，固定 bundle identifier、产品描述、版权、窗口最小尺寸与正式图标，bundle targets 明确为 Windows MSI/NSIS、macOS app/dmg、Linux AppImage/deb。CI 使用三平台矩阵执行前后端测试、release build、安装/启动烟雾脚本和产物元数据检查；恢复往返与旧 schema fixture 在主平台自动验证，三平台验证安装和首启。性能基线脚本输出 JSON artifact，阈值超出使 release job 失败。

签名、公证和自动更新需要外部凭据与发布基础设施，M4 仅预留 CI secret 名称与文档接口，不提交密钥也不把未签名开发产物描述为已签名。

**备选**：单平台交叉编译全部安装包（否决，WebView 与原生打包工具必须在目标系统验证）；把签名纳入本里程碑（否决，当前没有凭据或发布身份决策）。

## Risks / Trade-offs

- [跨库写入屏障需要所有修改路径配合，遗漏会破坏备份时间点] → 将闸门下沉到 `AppStateInner` 的连接访问器并禁止 command 直接锁裸连接；用并发写入 fixture 验证快照
- [附件在快照后、复制前被外部进程修改] → 清单固定元数据并在复制时/压缩前双重哈希；不一致使整包失败并提示重试
- [ZIP 炸弹或路径穿越损害恢复目录] → 只读取 manifest 声明项，限制文件数、单项与总展开大小，规范化路径并拒绝链接
- [内置 PDF renderer 与浏览器显示存在差异] → 以 PortableDocument 支持集为契约，建立中英文、表格、图片 golden fixtures；打印保留浏览器排版供高保真纸张输出
- [iCalendar 时区数据库和外部客户端实现差异] → 保存原 TZID，对未知时区拒绝静默换算；用主流客户端导出 fixture 做往返测试并报告未支持属性
- [托盘在部分 Linux 桌面不可用] → 启动探测失败后禁用关闭到托盘并保留普通窗口关闭语义
- [全局快捷键可能侵入用户系统习惯] → 默认仅注册明确的少量组合，所有组合可停用，交换注册保持原配置可回退
- [一次里程碑横跨数据、桌面与发布，回归面大] → 按可移植性、备份、桌面体验、打磨、发布五个可独立验收的工作流推进，每段保持 M1–M3 测试全绿
- [恢复失败时旧目录占用大量空间] → 成功启动后提示用户确认删除，自动清理只处理有 marker 和 nonce 的受管理目录

## Migration Plan

1. 先新增向前兼容迁移：meta 加入模板与 M4 偏好；tasks 加入笔记来源与同步队列；calendar 加入 external UID 与 taggings；space 加入加密 section templates。旧应用看不到新表但既有表结构保持可读。
2. 引入维护闸门与连接访问器，迁移所有修改 commands，再实现只读的备份创建和往返验证；恢复功能在备份格式固定后启用。
3. 实现 portability 和聚合能力，随后接入前端页面/日历入口、命令面板、标签与模板。功能开关仅用于开发期，合并前移除隐藏路径。
4. 接入 preferences、i18n、主题、动作注册表，再接 Tauri dialog/global-shortcut/tray/single-instance 权限与生命周期。
5. 把版本从 0.1.0 升到 1.0.0，验证从 M3 最新 schema fixture 升级、备份恢复往返和三平台 bundle；发布前保留用户数据原样，无需一次性内容重写。
6. 若 M4 新迁移在预发布阶段失败，停止启动并提示从自动生成的迁移前备份恢复；不提供 schema 降级。发布产物回滚到旧二进制前必须先恢复旧版本可读的备份。

## Open Questions

无。安装包签名、公证、自动更新与正式发布渠道依赖外部凭据和分发账户，已明确作为后续发布运维工作，不影响本变更的实现契约与任务拆分。
