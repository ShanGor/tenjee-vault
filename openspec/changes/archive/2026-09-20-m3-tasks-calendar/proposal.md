# Proposal: M3 任务模块 + 日程模块（含农历）

## Why

M1/M2 已交付技术地基与笔记模块：多库存储与迁移体系、加密原语、笔记层级组织、TipTap 编辑器、加密分区全生命周期、FTS5 搜索均已就位并有测试覆盖。`tasks.db` 与 `calendar.db` 的初始 schema 也已随 M1 落地（`migrations/tasks|calendar/0001_init.sql`），但两个领域库目前没有任何业务逻辑——`src/modules/tasks/` 与 `src/modules/calendar/` 仍是占位文件，应用也没有模块级导航（App.tsx 直接渲染笔记界面）。M3 按 `spec.md` §4.1/§4.2 交付任务与日程两大核心模块（含农历支持），让产品的三大模块全部可用，用户可以在同一应用内管理笔记、任务与日程并互相联动。

## What Changes

- **任务模块**：自定义任务列表 CRUD 与排序；多级子任务；任务属性（状态待办/进行中/完成/取消、优先级无/低/中/高、截止日期与时间、提醒、重复规则、富文本备注、标签、附件）；完成时间记录与已完成任务归档/恢复；列表视图 + 看板视图（按状态分列）+ 今日/本周/逾期智能视图；拖拽排序、批量操作、快速添加
- **日程模块**：月/周/日/议程四种视图；事件 CRUD（标题、描述、地点、开始/结束时间、全天、时区、颜色）；拖拽创建与调整事件；RFC 5545 RRULE 重复（每日/每周/每月/每年、自定义间隔、结束条件）与单次例外修改/取消；应用内多提前量提醒（Tauri Notification）
- **农历支持**：月/周/日视图在公历日期旁叠加农历日期（初一/十五）与节气显示（可开关）；按农历创建与重复的事件（如农历生日、每年正月初一），支持闰月规则（默认忽略闰月/指定闰月）；内置传统节日与二十四节气显示（可开关）；纯本地历法换算（Rust 端内置 1900–2100 查表），不依赖网络
- **模块联动**：事件可关联笔记页面（`space_id:page_id`）与任务，联动目标缺失时降级显示；任务拖拽到日历生成事件
- **应用外壳**：新增模块级导航（笔记/任务/日程切换），任务与日程模块挂入前端路由
- **数据层扩展**：`tasks.db` 新增 `attachments`/`taggings`/FTS5 索引迁移；`calendar.db` 新增事件 FTS5 索引迁移与多提醒存储（spec §4.1 要求可设多个提前量，而 M1 的 `events.reminder_minutes` 仅支持单个，需扩展 schema）
- **搜索**：任务（标题+备注）与事件（标题+描述）纳入 FTS5 索引体系，各模块内可搜索，后端提供跨库聚合查询能力（跨模块全局搜索 UI 属 M4 命令面板）
- **后端**：新增 `src-tauri/src/tasks/`、`src-tauri/src/calendar/`（含农历换算子模块）、`src-tauri/src/remind/` 提醒调度，及对应 Tauri commands

非目标（本变更不做）：
- 日历 `.ics` 导入导出（spec §4.1 列入日程模块，但按 M2 确立的先例——导入导出统一归属里程碑 M4）
- 任务快速添加的自然语言日期解析（spec §4.2 标注为可选；M3 提供基础快速添加输入，NLP 解析延后至 M4 打磨）
- 命令面板、全局快捷键、系统托盘、统一标签汇总视图、多语言与主题体系（M4 通用功能）
- 笔记侧编辑器改动（待办复选框与任务模块的深度打通属 M4 打磨）

## Capabilities

### New Capabilities

- `tasks-module`: 任务模块的完整行为规格——任务列表管理、多级子任务、任务属性（状态/优先级/截止/提醒/重复/备注/标签/附件）、完成归档与恢复、列表/看板/智能视图呈现与排序、批量操作与快速添加、任务的 FTS5 搜索、任务到日程事件的联动
- `calendar-module`: 日程模块的完整行为规格——月/周/日/议程视图、事件 CRUD 与拖拽调整、RRULE 重复与单次例外、多提前量应用内提醒、农历日期叠加显示与农历重复事件（含闰月规则）、传统节日与二十四节气显示、事件与笔记页面/任务的关联

### Modified Capabilities

（无——`data-storage` 的多库架构与迁移体系在 M1 已定型，本变更仅按既有迁移机制向 `tasks.db`/`calendar.db` 追加版本化迁移；`crypto-core`、`notes-module`、`app-skeleton` 的需求不变，本变更仅消费其能力。）

## Impact

- **代码**：新建 `src-tauri/src/tasks/`、`src-tauri/src/calendar/`（含 `lunar.rs` 历法换算）、`src-tauri/src/remind/`（提醒调度）；扩展 `src-tauri/src/search/` 与 `src-tauri/src/commands/`；重写 `src/modules/tasks/`、`src/modules/calendar/`（当前为占位），新增应用外壳导航，扩展 `src/shared/`
- **依赖**：Rust 新增 `tauri-plugin-notification`（提醒通知）；重复规则与农历换算按 design 决策自研有界子集或引入轻量 crate（见 design.md）；前端新增日历/看板视图所需组件（手写轻量组件，沿用 M2 选型原则，不引重型组件库）
- **数据**：`tasks.db` 迁移 `0002`（attachments、taggings、FTS5）；`calendar.db` 迁移 `0002`（FTS5、多提醒表，原 `reminder_minutes` 列数据迁入后废弃）；均为增量迁移，既有数据保留
- **兼容**：全部为新增能力，无破坏性变更；跨库引用沿用 M1 的「仅存 ID、应用层容错」原则
- **风险**：农历换算与节气算法的正确性需以权威日期对照表做充分测试；RRULE 展开与例外合并的边界情况（月末、闰年、时区）；提醒调度在应用休眠/未运行时错过提醒的补偿策略；拖拽交互（排序、跨视图、跨模块）的状态一致性
